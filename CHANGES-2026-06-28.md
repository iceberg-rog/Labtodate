## Files changed

### `src/app/api/stripe/webhook/route.ts` — BUG-039 fix (one hunk, `checkout.session.expired` branch)
- **Why:** the expired branch checked `existing.status === 'PENDING_PAYMENT'`
  against a stale in-memory snapshot, then issued an **unconditional**
  `prisma.order.update({where:{id}})` to CANCELED followed by an **unconditional**
  per-item `product.update({quantity:{increment}})` restock. Two redelivered
  `expired` events (Stripe redelivers on network blips / 5xx) that both snapshot
  PENDING_PAYMENT before either writes would both run the restock loop → the same
  units returned to the catalog twice (oversell risk) + double cancel. Violates F4
  (release stock once) and S4 (cancel returns stock once and only once).
- **Change:** unconditional `update` → atomic
  `const claim = await prisma.order.updateMany({ where:{ id: orderId, status:'PENDING_PAYMENT' }, data:{ status:'CANCELED' } })`,
  with the restock loop gated behind `if (claim.count === 1) { … }`. Only the
  writer that flips the row releases stock; a redelivered event claims zero rows
  and no-ops. Symmetric with every admin/buyer sibling.
- **Scope note:** this path is **dead under the official manual-payment posture**
  (Stripe not configured on prod — BUG-013), so no production impact today. It is
  hardened because it is Stripe-path code the owner wants kept future-ready;
  leaving the last instance of the anti-pattern in-tree is an avoidable latent
  defect the moment Stripe is enabled.
- **Posture:** manual-payment safe — webhook server logic, no UI; no Stripe/card/
  "pay now" copy touched. No schema change. Future-Stripe-readiness intact.
- Applied via count-asserted (`==1`) shell-side Python exact-match byte
  replacement + `os.replace`/`fsync`; **Edit tool not used on source**. File is LF;
  no CRLF introduced (`grep -c $'\r'` = 0). `diff` vs backup = the one intended
  hunk only.
