### `src/app/admin/actions.ts` — BUG-040 (P3, audit-integrity)
`archiveOrder` and `unarchiveOrder` were the last admin order mutations using the
snapshot-guard + **unconditional** `order.update` + **unconditional** `audit()`
pattern. A concurrent double-click / duplicate submit passed the in-memory
`if (o.archivedAt)` guard twice, wrote twice (re-stamping `archivedAt`), and emitted
a duplicate `order.archive` / `order.unarchive` audit entry.

Fix: kept the friendly fast-path guard, then replaced the unconditional write with
an atomic claim and gated `audit()` + the success return on `count === 1`:
- archive:   `updateMany({ where:{ id, archivedAt: null }, data:{ archivedAt: new Date(), archivedById } })`
- unarchive: `updateMany({ where:{ id, archivedAt: { not: null } }, data:{ archivedAt: null, archivedById: null } })`

A request that loses the race claims zero rows and returns the idempotent
"already archived" / "not archived" message without auditing. Two hunks only;
2722 → 2738 lines; LF preserved (no CRLF). Applied via shell-side count-asserted
Python byte replacement (Edit tool not used on source). Backup:
`.backups/bug040-2026-06-30/actions.ts.bak`.
