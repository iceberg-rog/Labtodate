## Code changes (BUG-030 — privilege-escalation gap closed)

15 mutating admin server actions were gated on role only (`requireAdmin()` /
`requireSession({ roles:['ADMIN'] })`) instead of a specific capability, defeating
the scoped-admin model. Each is now `requireCapability(<cap>)`, with the cap chosen
to match the existing admin-nav section gating (`src/app/admin/layout.tsx`).

### `src/app/admin/actions.ts`
- `requireCap` helper now **returns** the session (`return requireCapability(...)`)
  so callers needing `session.user.id` can adopt it (backward-compatible).
- `createTestimonial` / `deleteTestimonial` / `toggleTestimonial` → `content:cms`
- `createCaseStudy` / `deleteCaseStudy` / `toggleCaseStudy` → `content:cms`
- `createFacility` / `deleteFacility` / `toggleFacility` → `content:cms`
- `testIntegration` / `verifySetting` → `settings:view`
- `replyToThread` → `messages:reply` (now `const session = await requireCap('messages:reply')`)
- `createBrand` / `updateBrand` / `deleteBrand` → `products:edit`

### `src/lib/sell/actions.ts`
- import: added `requireCapability`
- `replySellSubmission` → `sell:reply`
- `proposeAcquisitionPrice` / `markAcquisitionReceived` / `completeAcquisition` /
  `uploadReceiptAndComplete` → `sell:status`

### `src/lib/assistant/actions.ts`
- import: dropped now-unused `requireSession`, added `requireCapability`
- `adminClaimConversation` / `adminReplyConversation` / `adminCloseConversation`
  → `messages:reply` (admin assistant surface lives under `/admin/messages`)

### `src/lib/content/actions.ts`
- import: `requireSession` → `requireCapability`
- shared `actor()` helper now `requireCapability('content:write', …)` — gates
  `createBlogPost` / `updateBlogPost` / `createWikiArticle` / `updateWikiArticle`
  (matches the Blog/Wiki nav and the already-correct `lib/blog/actions.ts`)
