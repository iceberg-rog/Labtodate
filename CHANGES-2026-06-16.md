### `src/lib/quotes/actions.ts` — `sendProforma`  (BUG-031, P3 → FIXED code)
WHY: the proforma `paymentInstructionsSnapshot` printed `Amount:` as the bare
subtotal (`parsed.priceCents`), but the materialized order stores
`totalCents = subtotal + shipping + tax`. At today's `DEFAULT_SHIPPING_CENTS=0` /
`DEFAULT_TAX_PERCENT=0` posture these agree; if the owner sets either nonzero,
the buyer would be instructed to bank-transfer LESS than the order total — an
under-payment / reconciliation hazard.

WHAT: immediately before building the snapshot, compute `proformaTotalCents`
with the identical formula the order-materialization block uses, and render:
- a single `Amount: <total>` line when total == subtotal (0/0 posture →
  byte-identical output to before), or
- an itemized `Subtotal / Shipping / Tax / Amount due` breakdown when shipping or
  tax is nonzero.
Order-creation math (F1-verified) was NOT touched — only the display was wrong.
Decision-neutral: does not decide whether quote orders should carry shipping/tax
(still the owner's call); only guarantees display == recorded order total.

HOW: single shell-side exact-match replacement (count-asserted = 1), LF
preserved. No Edit-tool use on source (per hardened 2026-06-11 rule).
