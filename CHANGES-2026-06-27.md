## Files changed

### `src/lib/orders/actions.ts` — BUG-038 fix (one hunk, in `confirmDelivery`)
- **Why:** `confirmDelivery` validated `status === 'SHIPPED'` against a stale
  in-memory snapshot, then issued an **unconditional**
  `prisma.order.update({ where:{ id } })` to DELIVERED and fired
  `notifyAdmins` + `audit` unconditionally. Two races:
  1. **Concurrent admin refund.** `refundOrder` claims any non-REFUNDED row
     (incl. SHIPPED): it flips SHIPPED→REFUNDED, **restocks**, and emails
     "refund issued"; then `confirmDelivery`'s unconditional write overwrites the
     row back to **DELIVERED** → terminal-state regression (REFUNDED→DELIVERED),
     stock already returned, money refunded, unit now oversellable. Violates S3
     (monotonic; REFUNDED terminal) and F12.
  2. **Buyer double-click** → `deliveredAt` re-stamped + admin double-notified
     (BUG-036-class double-notify).
- **Change:** unconditional `update` → conditional
  `updateMany({ where:{ id, status:'SHIPPED' }, data:{ status:'DELIVERED', deliveredAt } })`
  plus `if (res.count !== 1) { revalidatePath(...); return; }` **before** any side
  effect. Symmetric with the admin siblings. The pre-existing already-DELIVERED
  idempotent early-return is unchanged. No status field set anywhere it wasn't
  before.
- **Posture:** manual-payment safe — no Stripe/card/"pay now" copy touched. No
  schema change. No Stripe coupling. Future-Stripe-readiness intact.
- Applied via count-asserted (`==1`) shell-side Python exact-match byte
  replacement + `os.replace`/`fsync`; **Edit tool not used on source**. First
  attempt normalized CRLF→LF on the whole file; caught by diff-vs-backup,
  reverted from backup, re-applied in **binary mode preserving CRLF**. Final diff
  vs `.backups/bug038-2026-06-27/actions.ts.bak` = the one intended hunk only.
  443 → 460 lines; CRLF preserved (438 → 455).
