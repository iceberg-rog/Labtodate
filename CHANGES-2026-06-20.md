## Files changed

### `src/app/admin/actions.ts` (modified)
Two functions, one defect class (non-atomic restock under concurrency):

- **`cancelOrder`** — replaced the unconditional
  `prisma.order.update({ where: { id }, data: { status: 'CANCELED' } })`
  with a conditional claim:
  ```ts
  const claim = await prisma.order.updateMany({
    where: { id, status: 'PENDING_PAYMENT', paymentSubmittedAt: null },
    data: { status: 'CANCELED' },
  });
  if (claim.count !== 1) return; // already canceled / no longer cancelable
  ```
  placed before the restock loop + buyer/admin notifications. The WHERE
  re-encodes the guards the snapshot read already checks (PENDING_PAYMENT, no
  receipt in flight per BUG-035), so the loser of a double-click race no-ops
  instead of restocking again.

- **`refundOrder`** — replaced the unconditional
  `prisma.order.update({ where: { id }, data: { status: 'REFUNDED' } })`
  with:
  ```ts
  const flip = await prisma.order.updateMany({
    where: { id, status: { not: 'REFUNDED' } },
    data: { status: 'REFUNDED' },
  });
  if (flip.count !== 1) return; // a concurrent click already refunded + restocked
  ```
  before the restock loop + refund email + notifications. The Stripe
  `refunds.create` call stays ahead of the flip and is itself replay-safe; the
  atomic flip is the sole gate that makes restock/email fire exactly once on the
  manual (no-PaymentIntent) path.

**Why:** the status precondition previously lived only in in-memory `if` checks
on a stale `findUnique` snapshot, never in the write's WHERE. Two interleaved
admin requests both passed the guard and both ran the restock loop →
`Product.quantity` double-incremented + buyer double-notified. Violated
invariant **S4** ("returns stock once and only once"). The fix adopts the exact
atomic-claim pattern `markOrderPaidManually` already uses.

**Posture:** no Stripe/card/"pay now" copy touched; no schema change; no Stripe
coupling added (the Stripe refund block is untouched → future-Stripe-ready).
`npx tsc --noEmit` = 0 before and after. Diff vs
`.backups/bug036-2026-06-20/actions.ts.bak` = only the two intended hunks.
File 2688 → 2707 lines; backticks unchanged (388); tail (`rejectPayment`) intact.

### `scripts/verify-restock-once-guard.ts` (new)
Offline concurrency regression matrix. Models a faithful two-concurrent-clicks
race (both requests snapshot the original row before either write lands) against
both OLD (unconditional `update`) and NEW (conditional `updateMany` + `count===1`
gate) logic for cancel and refund. Asserts NEW restocks exactly once
(`restockRuns=1, stock=+3, notifies=1`) and documents OLD double-restocking
(`restockRuns=2, stock=+6, notifies=2`). Run:
`node --experimental-strip-types scripts/verify-restock-once-guard.ts` (exit 0).
Sensitive: revert either NEW path to an unconditional update → restockRuns flips
to 2 → exit 1. (`npx tsx` unavailable in the Linux sandbox — node_modules
carries the Windows esbuild binary.)

### `scripts/verify-receipt-in-flight-guards.ts` (modified — 1 line)
Added `export {};` module marker so it no longer collides with the new harness
on shared top-level identifiers (`OrderStatus`/`failures`/`rows`) in the
`**/*.ts` tsconfig program. No logic change; still exit 0.
