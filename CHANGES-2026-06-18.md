## Source changes

### `src/app/api/cron/sla-sweep/route.ts` — BUG-034 fix (P1, data-integrity/trust)
The proforma-expiry sweep cancelled the linked order on `status:'PENDING_PAYMENT'`
alone. Because submitting a receipt leaves an order at `PENDING_PAYMENT` (only
`paymentVerificationStatus` flips to `AWAITING_VERIFICATION`; admin verify is the
sole path to PAID), a proforma expiring in the window before an admin verified
would auto-cancel a buyer's already-paid order and move the deal to "Lost".

Two changes, both tightly scoped:
1. Added a pre-check: `findFirst` a linked order with
   `status:'PENDING_PAYMENT'` AND `paymentSubmittedAt: { not: null }`. If found,
   `continue` — skip the entire expiry action (no proforma close, no order
   cancel). The buyer acted before expiry; leave it for the admin verify/reject
   queue.
2. Defense-in-depth: added `paymentSubmittedAt: null` to the linked-order cancel
   `updateMany` WHERE, closing the race between the pre-check and the
   transaction. This mirrors the orphan-order sweep directly below, which
   already guards on `paymentSubmittedAt`.

No schema change. No Stripe coupling. No UI copy touched. Strengthens the
manual-payment posture (only admin verify/reject changes payment state; no cron
may evict a paid-but-unverified order from the queue).
