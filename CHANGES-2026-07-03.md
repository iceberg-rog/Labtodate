## Summary
One new bug found and fixed this round: **BUG-043** — `refundOrder` was the last
money-mutating server action still using a **negative** status guard
(`status: { not: 'REFUNDED' }`) instead of a positive money-captured allow-list.
That over-broad WHERE would let a refund run on a `CANCELED` order (already
restocked → double-restock → phantom inventory of a unique unit) or a
`PENDING_PAYMENT` order (no money captured → false "refund" email + REFUNDED
stamp). Fixed by re-encoding a positive `REFUNDABLE = PAID/PROCESSING/SHIPPED/
DELIVERED` allow-list in both the snapshot guard and the atomic write, keeping the
existing `count===1` gate. Classed **P3** (defense-in-depth): not currently
reachable through the shipped UI, but closes a latent gap and makes `refundOrder`
consistent with every sibling money-path action.

`npx tsc --noEmit` → exit 0 before and after. All 9 offline matrices exit 0.

## Files changed

### `src/app/admin/actions.ts` — MODIFIED (BUG-043 fix)
- `refundOrder`: replaced `if (order.status === 'REFUNDED') return;` with a positive
  `const REFUNDABLE = ['PAID','PROCESSING','SHIPPED','DELIVERED'] as const;` snapshot
  guard (`if (!REFUNDABLE.includes(order.status)) return;`) placed **before** the
  Stripe refund call / restock / email.
- Changed the atomic flip WHERE from `status: { not: 'REFUNDED' }` to
  `status: { in: [...REFUNDABLE] }`. Restock + buyer/admin notifications remain gated
  on `flip.count === 1`.
- Why: every sibling (`cancelOrder`, `markOrderPaidManually`, `verifyPayment`,
  `rejectPayment`) positively re-encodes its allowed source-status in the write;
  `refundOrder` was the lone exception. The negative guard matched CANCELED /
  PENDING_PAYMENT rows, so a stale/direct server-action POST (or any future caller)
  could double-restock a unique unit or false-refund an uncaptured order.
- No behavioural change on the happy path (refunding a PAID-family order restocks
  once, emails once, stamps REFUNDED once). Stripe refund path untouched — only runs
  when `stripePaymentIntentId` exists; future-Stripe-ready and manual-payment-safe.

### `scripts/verify-refund-status-guard.ts` — NEW (offline regression matrix)
- Models refundOrder's status precondition OLD vs NEW across PAID / already-REFUNDED

  refunds a captured order exactly once, no-ops on CANCELED + PENDING_PAYMENT, stays
  idempotent on REFUNDED; documents OLD double-restocking CANCELED and false-refunding
