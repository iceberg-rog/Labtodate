## Summary
One new bug found and fixed this round: **BUG-042** — the SLA-breach sweep in the
cron was the last unguarded (non-atomic) write path in `sla-sweep/route.ts`.
Overlapping cron invocations could double-notify/double-email/double-audit a single
breach. Fixed with the same atomic-claim + `count===1` gate the rest of that route
(proforma-expiry, orphan-order) and the whole order-status family already use.

`npx tsc --noEmit` → exit 0 before and after. All 8 offline matrices exit 0.

## Files changed

### `src/app/api/cron/sla-sweep/route.ts` — MODIFIED (BUG-042 fix)
- **Support-ticket sweep** (`for (const t of overdueTickets)`): replaced the plain
  `prisma.supportTicket.update({ where: { id: t.id }, data: { slaBreachAt: now } })`
  with an atomic
  `updateMany({ where: { id: t.id, slaBreachAt: null }, data: { slaBreachAt: now } })`
  and added `if (claim.count !== 1) continue;` before any notify/email/audit.
- **Quote sweep** (`for (const q of overdueQuotes)`): same change on
  `prisma.sourcingRequest`.
- Why: the route is exported for both POST and GET (GET → POST for sidecar wget),
  and a slow sweep can overlap the next scheduled tick. Both invocations read the
  same `slaBreachAt=null` row before either write lands, so the old unconditional
  update + notify fired every side effect twice. The precondition now lives in the
  write's WHERE, mirroring the proforma/orphan sweeps directly below in the same file.
- No behavioural change on the single-invocation happy path; `ticketsNotified` /
  `quotesNotified` counters now reflect deduped (actual) notifications.
